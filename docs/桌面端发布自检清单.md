# 桌面端发布自检清单

> 适用产物：`dist/LicTracer/`（onedir 整目录，zip 分发）
> 构建方式：仓库根 `powershell -ExecutionPolicy Bypass -File packaging\build_exe.ps1`
> 原则：**每一项都必须在「干净机器」上核验通过才可交付**——开发机因装有 Python 与项目依赖，无法暴露打包缺失问题。

## A. 干净 Windows 机器准备

- [ ] 目标机为 Windows 10/11 x64，**未安装 Python**（或已验证 PATH 中无 python 干扰）
- [ ] 将整个 `dist/LicTracer` 目录拷贝/解压到目标机本地磁盘（避免直接从网络盘运行）

## B. 启动与资源加载

- [ ] **运行自检探针**：在 exe 同目录打开终端执行 `LicTracer.exe --selfcheck`，
      确认退出码为 0 且生成 `selfcheck_result.txt`，首行为 `SELFCHECK OK`，
      且 `tree_sitter = available`、`kb_files ≥ 1`（frozen 路径与内置 KB 的机器级验证）。
      若显示 FAILED，文件内含完整 traceback，直接定位缺失模块。
- [ ] 双击 `LicTracer.exe`，主窗口在 15 秒内出现，无控制台黑窗残留、无「缺少 xxx.dll」报错
- [ ] exe 文件、任务栏、窗口左上角均显示**蓝底盾牌应用图标**（缺失说明 assets 未随包）
- [ ] 窗口标题含「本地离线 / 代码不出本机」标识
- [ ] 首次启动无杀软误拦截；若被 SmartScreen 提示，记录截图（无签名 exe 的正常现象）

## C. 核心功能走查（用内置示例或小型项目）

- [ ] 拖入 / 选择一个含 `.py` 的文件夹 → 文件列表正确出现且排除 `__pycache__/.venv` 等
- [ ] 筛选框输入子串 → 列表实时过滤；全选/全不选生效
- [ ] 知识库路径留空 → 校验清单显示「使用内置默认知识库」→ 点「开始审计」能出结果
      （此步是 **frozen 路径解析**的关键验证：内置 KB 位于 `_internal/data/knowledge_base`）
- [ ] 进度条按 已处理/总数 推进，显示当前文件名；大目录下点「取消」能在当前文件完成后停止
- [ ] 项目级结论卡片颜色正确：INCOMPATIBLE=红 / NEEDS_REVIEW=黄 / COMPATIBLE=绿，命中统计合理
- [ ] 明细表可展开逐片段行（L1-L4、主证据 ✓、驱动结论 ✓）；双击文件行弹出证据链对话框
- [ ] 构造归属歧义场景（可选，基准语料 q037 类多源并列）时 ⚠ 歧义标注出现
- [ ] 方法学透明条显示 tree-sitter 状态 / 检索模式 / KB 文件数 / 锚点门槛；
      若目标机出现「正则降级」字样即为异常，须回查 tree-sitter 收集
- [ ] 高级项：自定义知识库路径覆盖后审计可用；清空后恢复默认
- [ ] 导出 Markdown / HTML 各一次，打开检查内容完整（含各文件分节）

## D. 离线承诺核验

- [ ] 断网状态下完整执行 C 节流程，全部功能可用（本应用设计上无任何网络请求；
      LLM 摘要保持默认关闭）
- [ ] 审计结束后确认目标机无新增可疑外联（可选：防火墙日志抽查）

## E. 记录归档

- [ ] 在本清单底部记录：目标机型号/系统版本、exe 大小与目录总大小、构建 commit hash、
      走查人、日期
- [ ] 发现的任何偏差回开发机修复后重新构建并重跑全表
