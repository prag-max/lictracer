> 背景：本项目为 AI 生成代码许可证合规审计系统，用于毕设/论文。本清单基于已完成的工作梳理后续优化项：

## P0 ｜答辩/论文前必做

### P0-1 实验与评估体系搭建（数据集 + 基线 + 指标）
- **状态**：⚠️ 大部分完成——✅ 评估体系已落地（2026-08-23）：受控合成基准（57 查询 × 7 类改写，`evaluation/generate_benchmark.py`）+ 真实开源语料基准（11 包 / 111 实体 / 484 查询，`evaluation/real_corpus.py`），五指标全 1.0、负样本零假阳性；⛔ 仍开：SOTA 基线对比（SourcererCC / JPlag 批处理跑分）——论文期工作。
- **预期收益**：论文"方法贡献"从无证据变为可量化。能以召回率/精确率/延迟三项硬指标证明粗筛层优于或持平 SOTA 基线，直接支撑"自研方法有效"的核心论点；也是答辩被问"你比 SourcererCC 好在哪"的唯一答案来源。
- **实施要点**：
  1. 构建带 license 标注的 KB + 查询集，含 T1/T2/T3 正负样本对（ground-truth 标签）。
  2. 基线：SourcererCC（Java，T1 100/T2 98/T3 93 召回）、JPlag（Java21+，O(N²) 批处理）——以批处理模式跑对比。
  3. 指标：粗筛召回率@K、精确率@K、端到端延迟、KB 扩容扩展性曲线。
  4. 实验脚本骨架落到 `tests/` 或新增 `bench/` 目录，结果存 CSV 供论文引用。
  5. 局限章节诚实标注：不覆盖语义 T4（合规上不需要，且避免误报）。

### P0-2 可复现性固化（版本锁定 + seed 文档化）
- **状态**：⚠️ 大部分完成——✅ `pyproject.toml` / `requirements.txt` 主依赖全量锁定（`osadl-matrix==2024.5.22.10535`、`datasketch==2.0.0`、tree-sitter 系列精确锁定）；✅ 可复现性口径（seed=1、索引缓存格式、确定性验证器）已在 README 固化；⛔ 仍开：传递依赖（numpy/scipy）的 freeze 归档；Dockerfile 子项随服务部署退役不再适用。另：2026-08-23 新增 OSADL 快照时效启动告警（`matrix_loader.warn_if_osadl_snapshot_stale`），快照过期不再无感。
- **预期收益**：正面防御 PRD「100% 可复现 / 零幻觉」声明被审稿人挑战。当前 `MinHash(num_perm=128, seed=1)` 已确定，但依赖树未全锁定，OSADL 结论受 `osadl-matrix` 版本牵制。
- **实施要点**：
  1. `requirements.txt` 显式锁定 `osadl-matrix==2024.5.22.10535`、`datasketch==2.0.0`、以及其传递依赖 `numpy`/`scipy` 版本（datasketch 2.0.0 引入 scipy，版本漂移会改变 MinHash 数值）。
  2. 在 `docs/技术架构设计文档.md` 或 README 单列"可复现性"小节：固定 `seed=1`、索引缓存格式、Python 版本。
  3. Dockerfile 用 `pip install --no-cache-dir -r requirements.txt`（已做），建议加 `pip freeze` 产物归档。

### P0-3 粗筛 token 粒度增强（运算符感知）—— ✅ 已实现（2026-08-21）
- **状态**：连同 Winnowing、AST 子树哈希一并落地于 `src/provenance/coarse_retriever.py`（多特征 MinHash 相似召回）。
- **结果**：tokenizer 改为 `re.findall(r"\w+|\S+", ...)` 保留运算符/标点（`x+0` vs `x*0` 实测 jaccard 0.5，旧版 1.0 不可区分）；Winnowing 滑动窗口对 T3 局部增删改鲁棒；AST 子树哈希提供结构信号（identifier→ID 抗重命名、注释跳过）。索引缓存升级为 `feature_index.pkl`（含管线版本号，旧缓存自动失效）。pytest 26 passed（新增 10 个溯源层测试）。
- **剩余局限**：AST 层字面量类型占位使"仅常量值不同"在 AST 特征不可见（token 层可见 + redup 兜底），已写入架构文档 §2.2 第 4 点与方案文档 §5。

- **状态**：✅ 已解决（2026-08-23，方式为**整体移除**而非调参）：`MinHashLSHForest` 与 `LICT_RETRIEVER_FOREST_MIN/K_MULT/CAND_FLOOR` 参数已删除，检索唯一路径为全库确定性 Jaccard 扫描（召回 100% 确定）；KB 为 O(百) 实体规模，实测毫秒级，本调优项随之失效。≥2000 文件规模代价列入 future work 边界标注。
- **预期收益**：当前 `LICT_RETRIEVER_K_MULT=3` / `LICT_RETRIEVER_CAND_FLOOR=50` 为经验值。评估驱动调优可在保延迟前提下最大化弱克隆召回（合规场景"宁可误报不可漏报"）。

### P1-4 检索器多 worker 冷启动一致性说明
- **状态**：⛔ 不再适用：FastAPI / Streamlit 多 worker 服务部署形态已退役（现役交付形态为 CLI + 规划中的桌面单机应用）；进程内缓存 + 磁盘索引缓存已覆盖全部现役场景。
- **预期收益**：当前进程内 `_RETRIEVER_CACHE` 在单进程有效；`uvicorn --workers N` 或 Streamlit 多会话下每个 worker 各自冷建索引（一次性 ~0.86s@100 文件，可缓存到磁盘 `.index` 故二次启动 ~2ms）。明确其可接受边界，避免论文/部署误以为"每次请求重建"。
- **实施要点**：
  1. 文档说明：磁盘索引缓存已消除"每请求重建"根因；多 worker 仅首请求各自建一次，后续命中磁盘缓存。
  2. 若未来压力测试需零冷启动，可改为 gunicorn 单 worker 或预构建索引脚本（`python -m src.provenance.coarse_retriever --build <kb>`）。

## P2 ｜后续/可选

### P2-1 删除根目录 `package.json`（NLCI 死文件）
- **状态**：✅ 已完成：根目录已无 `package.json`，无 Node 相关残留。
- **预期收益**：清理误导——该文件仅依赖 `@nlci/cli`/`@nlci/core`（NLCI 已弃用），无任何代码引用（grep 确认 0 处引用），留在仓库会让读者误以为仍依赖 Node。
- **实施要点**：直接删除；同步检查 README/Dockerfile 是否还有 node 相关残留（已确认无）。

### P2-2 查询 MinHash 重建开销微优化（~8ms/请求固定开销）
- **预期收益**：端到端 `retrieve` 含每次重建查询 MinHash（~8ms），在 N<2000 处掩盖 forest 优势。微优化可进一步压延迟。边际收益，非瓶颈。
- **实施要点**：流水线 `analyze_file` 已产出规范化骨架，使 `CoarseRetriever.retrieve(skeleton)` 直接收 token 序列、跳过重复 normalize+分词；查询唯一不可缓存，仅省预处理。

### P2-3 语义 T4 可选补充信号（CodeBERT+FAISS，仅辅助）
- **预期收益**：覆盖"有意改写以规避检测"的强克隆（功能等价结构不同），提升完整性。
- **实施要点**：
  1. **绝不**作为侵权判定门——仅输出 `semantic_hint` 辅助字段。
  2. 论文须明确：T4 独立重写法律不构成派生作品，语义相似做门控会产生高危害误报；故仅作"建议人工复核"信号。
  3. 引入 torch 依赖，与"轻依赖"原则冲突，默认关闭。

### P2-4 KB 增量索引
- **预期收益**：当前 KB 文件清单变更即全量重建索引；长期演进的大规模 KB 可改为按文件增量增删 MinHash。
- **实施要点**：索引结构改为 per-file 记录 + 增量 merge；超出当前毕设规模后再做。

### P2-5 多语言扩展
- **预期收益**：当前仅 Python（`ast_normalizer` tree-sitter py）。扩展适用性。
- **实施要点**：tree-sitter 多语言 grammar；`normalize` 按语言分派；超出当前"Python 代码审计"范围，作为未来工作。
