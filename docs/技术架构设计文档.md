# 技术架构设计文档

## 1. 整体架构图（主体流程）

> 图表生成中...（原网页图表占位，主体流程如下）

原始代码文件（.py）
→ 预处理层（tree-sitter：AST 解析与规范化，变量名统一化）
→ 溯源核心层（datasketch MinHash：从知识库召回 Top-K 相似候选）
→ 证据精炼层（redup：细粒度扫描，输出行级证据 JSON）
→ 多源结果聚合节点（自研：按行号聚类，拆分不同来源片段）
→ 合规推理层（自研：OSADL 矩阵 + Copyleft 传染判断）
→ 报告生成层（大模型 API：自然语言摘要）
→ 输出结构化合规报告（JSON + Markdown + HTML）

## 2. 模块详细设计

### 2.1 预处理层（Preprocessing Layer）

| 属性        | 说明                       |
| --------- | ------------------------ |
| **职责**    | 代码解析、AST 生成与规范化          |
| **核心技术**  | tree-sitter              |
| **输入**    | 原始代码文件（.py）              |
| **输出**    | 规范化后的 AST（变量名统一化、去除注释）   |
| **自研/集成** | 集成 tree-sitter，自研调用与编排逻辑 |

**关键逻辑**：

- 使用 tree-sitter 解析代码生成 AST
- 遍历 AST，将所有标识符（变量名、函数名）替换为占位符（如 `VAR_0`, `FUNC_1`）
- 输出纯结构骨架，用于后续溯源

### 2.2 溯源层（Provenance Layer）

| 属性        | 说明                                 |
| --------- | ---------------------------------- |
| **职责**    | 从知识库中快速召回相似候选代码                    |
| **核心技术**  | datasketch MinHash + Winnowing + AST 子树哈希（词法/结构克隆 T1/T2/T3） |
| **输入**    | 待审计的原始 Python 源码                    |
| **输出**    | Top-K 相似候选列表（文件路径、相似度评分）           |
| **自研/集成** | 完全自研：多特征 MinHash 相似召回（运算符感知分词 + Winnowing 指纹 + AST 子树哈希）+ datasketch MinHash + 离线索引缓存，无 Node 依赖 |

> **注意**：NLCI 严格依赖 `node>=18<19` 已弃用；溯源召回改为纯 Python 的 datasketch MinHash 近似相似。离线对知识库每个文件预计算 MinHash 并持久化缓存（`<kb>/.index/feature_index.pkl`，含特征管线版本号，变更自动失效重建），在线仅做 jaccard 估计排序，完全确定、可复现，且消除原全库 `SequenceMatcher` 的 O(N×M) 瓶颈（51.4s → ~6ms/请求）。

**特征管线（多特征 MinHash 相似召回，提升召回率与准确率）**：

1. **运算符感知分词**：对规范化骨架（`normalize`，天然抗重命名）做 `re.findall(r"\w+|\S+", ...)` 分词——保留运算符与标点，多字符运算符（`==`/`>=`）整体保留，运算符级改动（`x + 0` vs `x * 0`）在粗筛层即可区分（实测 jaccard 0.5，旧版为 1.0 不可区分）
2. **Winnowing（MOSS 式指纹）**：滑动窗口（默认 15，`LICT_WINNOW_WINDOW` 可配）内取最小 token 哈希为代表指纹，对局部增删改（T3）鲁棒——单点改动只影响窗口内局部指纹
3. **AST 子树哈希（Merkle）**：tree-sitter 解析后自底向上为每个节点计算结构哈希（identifier→`ID` 占位抗重命名 T2、字面量→类型占位抗常量改写、注释节点跳过），提供独立于线性 token 顺序的结构信号
4. 合并特征集 → MinHash(128, `seed=1`) → 全库确定性 Jaccard 扫描（O(N×num_perm) 整数级比较，召回确定性 100%；KB 为提取实体集 O(百) 文件，远低于 LSH Forest 亚线性代价生效的 2000+ 文件阈值，故 Forest 已于 2026-08-23 移除）

**关键逻辑**：

1. 离线阶段：对知识库每个文件提取多特征（运算符感知分词 + Winnowing 指纹 + AST 子树哈希）→ MinHash，持久化到 `<kb>/.index/feature_index.pkl`（KB 文件清单变更或特征管线版本变更自动失效重建）
2. 在线阶段：查询源码 → 提取多特征（运算符感知分词 + Winnowing 指纹 + AST 子树哈希）→ MinHash → 与全库候选做 jaccard 估计并排序 → 取 Top-K 相似候选
3. 方法路线刻意不引入语义嵌入：语义等价但结构独立的重写（T4）在法律上属独立派生作品、不构成侵权，用语义模型做粗筛会将其误判为克隆，产生高危害误报
4. **剩余粒度局限（须如实标注）**：AST 层对字面量做类型占位（integer/float→`NUM`、字符串→`STR`），因此"仅常量值不同"的改写（如 `x + 1` vs `x + 2`）在 AST 特征不可见——但 token 层（Winnowing）保留字面量文本，该差异在 token 特征可见，且由下游 `redup` 行级比对兜底；若同时改写运算符与常量结构（更强 T3），依赖 Winnowing 窗口与 redup 的联合捕获。论文"局限性"章节应明确此点

### 2.3 证据精炼层（Evidence Refinement Layer）

| 属性        | 说明                           |
| --------- | ---------------------------- |
| **职责**    | 对候选进行细粒度扫描，输出行级证据            |
| **核心技术**  | redup                        |
| **输入**    | 溯源召回返回的候选文件列表               |
| **输出**    | 结构化 JSON 证据（文件路径、行号、函数名、相似度） |
| **自研/集成** | 集成 redup，自研结果解析与格式化          |

**关键逻辑**：

1. 对每个候选文件，调用 `redup.core.comparator.compare_projects` 进行跨项目结构/相似性比对
2. 解析返回的匹配结果，提取 `file_b`、行号区间 `lines_a`（`line_start`/`line_end`）、`similarity`
3. 按 `_MIN_SIMILARITY` 阈值过滤，并转换为统一的证据格式 `{file, project, license, line_start, line_end, similarity}`

### 2.4 多源结果聚合节点（Multi-Source Aggregation Node）

| 属性        | 说明                                      |
| --------- | --------------------------------------- |
| **职责**    | 处理 AI 代码混剪特征，拆分不同来源片段                   |
| **核心技术**  | 自研"片段-来源"映射算法                           |
| **输入**    | 证据精炼层输出的所有候选匹配（含行号范围）                   |
| **输出**    | 结构化映射表：`[{片段ID, 行号范围, 来源项目, 许可证, 相似度}]` |
| **自研/集成** | **完全自研**                                |

**关键逻辑（伪代码）**：

```
输入：evidence_list = [{file, line_start, line_end, source_project, similarity}, ...]

1. 按 line_start 对 evidence_list 排序
2. 初始化 segments = []
3. 遍历 evidence_list：
   a. 如果当前证据与上一个证据的行号范围重叠或间隔 < 3 行：
      合并为同一片段（保留相似度最高的来源）
   b. 否则：
      创建新片段
4. 对每个片段，查询知识库获取其许可证
5. 输出 segments = [{id, lines, source, license, score}, ...]
```

### 2.5 合规推理层（Compliance Reasoning Layer）

| 属性        | 说明                                                  |
| --------- | --------------------------------------------------- |
| **职责**    | 多许可证叠加推演与 Copyleft 传染判断                             |
| **核心技术**  | 自研规则引擎 + license-expression + OSADL 矩阵              |
| **输入**    | 多源聚合节点输出的映射表                                        |
| **输出**    | 确定性合规结论（兼容/不兼容/需复核）+ 推演证据链                          |
| **自研/集成** | 自研推理逻辑；集成 license-expression（解析）、osadl-matrix（数据查询） |

**关键逻辑（伪代码）**：

```
输入：segments = [{id, lines, source, license, score}, ...]

1. 对每个 segment.license，调用 license-expression 标准化为 SPDX 格式
2. 对每个标准化后的许可证，调用 osadl_matrix.is_compatible(license, project_license)
3. 如果存在任何 "NO"：
   a. 检查是否为 GPL 系列许可证
   b. 如果是，执行 Copyleft 传染判断：
      - 如果链接方式为 "static" → 整个项目必须开源
      - 如果链接方式为 "dynamic" → 仅该片段受影响
4. 输出结论：COMPATIBLE / INCOMPATIBLE / NEEDS_REVIEW
5. 同时输出推演步骤作为证据链
```

**Copyleft 规则配置示例（YAML）**：

```yaml
copyleft_rules:
  - license_pattern: "GPL-*"
    link_type: "static"
    action: "project_must_open_source"
  - license_pattern: "GPL-*"
    link_type: "dynamic"
    action: "segment_only"
  - license_pattern: "AGPL-*"
    action: "project_must_open_source"
```

### 2.6 报告生成层（Reporting Layer）

| 属性        | 说明                                 |
| --------- | ---------------------------------- |
| **职责**    | 将技术证据转化为自然语言报告                     |
| **核心技术**  | 大模型 API（GPT-4o-mini / DeepSeek-V3） |
| **输入**    | 合规推理层的结论 + 证据链                     |
| **输出**    | 自然语言审计报告（含摘要、风险等级、整改建议）            |
| **自研/集成** | 自研 Prompt 设计与调用编排；集成大模型 API        |

> **关键原则**：大模型仅作"翻译官"，不参与任何合规判断。
